Change
When the sponsor requests a new feature, the project manager should not implement it immediately. First, the project manager should record the request as a formal change request. Then the team should analyze the impact of the change on scope, schedule, cost, quality, risk, communication, and stakeholders.

In this case, the email notification function will increase the project scope, require two more weeks of development, increase testing effort, and may cause schedule delay and budget overrun. Therefore, the change request should be submitted to the Perform Integrated Change Control process.

During integrated change control, the change request should be reviewed, approved or rejected by the sponsor, steering group, or change control board. The decision should be recorded in the change log and communicated to all relevant stakeholders.

If the change is approved, the project manager should update the project management plan, scope baseline, schedule baseline, cost baseline, requirements documentation, and risk register. The approved change request should then be implemented through Direct and Manage Project Work. After implementation, the project manager should continue to monitor the schedule, cost, quality, and risks to ensure that the change is properly controlled.

If the change is rejected, the project should continue according to the original approved project management plan.
